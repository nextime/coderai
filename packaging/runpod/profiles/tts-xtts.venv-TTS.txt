# transformers refuses a `device_map`/`torch.device` load without accelerate, so
# a pod boots healthy, answers /v1/models, and then fails EVERY request with
#   Model '<name>' failed to load: Using a `device_map` ... requires `accelerate`
# which reads as a model problem rather than an image problem. Measured on a
# real A40 for the embeddings image: 303s of boot paid before anyone could find
# out. Every profile that carries transformers carries this with it.
accelerate>=0.26.0
coqui-tts>=0.24.0
# coqui-tts imports click at module load but does not declare it, so the venv
# installs cleanly and then fails its import check. Found by iterating the venv
# in a container — two minutes — rather than one image build per missing module,
# which is what the audiocraft venv cost before that lesson took.
click>=8.0
soundfile>=0.12.0
