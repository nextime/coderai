# Screening generated media — `POST /v1/moderation`

Four checks over an image, or over frames sampled from a video: how explicit it
is, where the faces are, how old they look, and whether they are the performer
who consented.

## The rule this endpoint is built around

**It fails closed.** Every reassuring value it can return —
`minor_detected: false`, `flagged: false`, `unmatched_faces: 0` — is a
statement that a model actually examined the content and found nothing. When a
model a requested check needs is missing or unloadable, the request is a
**503** naming the model, not a result with that check quietly absent.

This is the whole point. A caller cannot tell a missing check from a passed
one, so an endpoint that degraded silently would be worse than no endpoint at
all: it would be a green light generated by a model that was never there.

Two consequences, both deliberate:

* **An explicit image with no detectable face cannot be cleared on age.** There
  is nothing to estimate an age from, so `minor_detected` comes back `null`
  (not `false`), `review_required` is true and the item is flagged. A body
  without a face is precisely the case you most need told about.
* **`minor_detected` keys on the low end of the age interval, not the point
  estimate.** A face estimated at 24 with an ±8-year band has a credible chance
  of being under 18 and is flagged. An age estimator's error is several years
  wide; a minor/adult decision made on one number is a decision made on noise.

A face too small to assess (under 48 px) is reported as a face with a `null`
age and `age_assessed: false`, and counts toward `faces_not_assessed` — it is
not an adult face.

None of this is legal advice or a substitute for your own obligations. It is a
screen, and the response says what was measured and by which model so you can
tell the difference.

## Ask what is available first

```http
GET /v1/moderation/models
```

```json
{"models": [{"id": "Falconsai/nsfw_image_detection", "role": "nsfw",
             "type": "moderation",
             "capabilities": ["moderation", "nsfw_detection"],
             "available": true},
            {"id": "insightface:genderage", "role": "age", "available": true},
            {"id": "buffalo_l", "role": "face", "available": true}],
 "unavailable": []}
```

Worth asking **before** sending content: an unavailable check is a 503 at
moderation time. The same entries appear in `/v1/models` as `type:
"moderation"`, with `available` saying whether each can be loaded right now.

## A request

```jsonc
POST /v1/moderation
{
  "input": [
    {"type": "image", "src": "/v1/files/out-1.png"},
    {"type": "video", "src": "/v1/files/out-2.mp4", "sample_fps": 1}
  ],
  "checks": ["nsfw", "age", "faces", "face_match"],
  "nsfw_threshold": 0.7,
  "face_match": {
    "reference": ["/v1/files/performer-selfie.jpg"],
    "character_profiles": ["performer-a"],   // or a saved profile
    "threshold": 0.6
  }
}
```

`src` takes a `/v1/files/…` reference, a URL, a local path or base64. An
unknown check name is a 400, never a skipped check.

## The response

```jsonc
{
  "results": [{
    "src": "/v1/files/out-1.png",
    "frames_examined": 1,
    "nsfw": {"score": 0.97, "labels": {"nsfw": 0.97, "normal": 0.03}},
    "faces": [{"frame": 0, "box": [x, y, w, h], "det_score": 0.93,
               "age_estimate": 27.0, "age_low": 19.0, "age_high": 35.0,
               "age_assessed": true, "minor_probability": 0.0,
               "match": {"reference": 0, "similarity": 0.83, "matched": true}}],
    "min_age_estimate": 19.0,
    "minor_detected": false,
    "unmatched_faces": 0,
    "review_required": false,
    "flagged": false,
    "reasons": []
  }],
  "flagged": false,
  "checks": ["nsfw", "age", "faces", "face_match"],
  "models": {"nsfw": "…", "age": "…", "face": "buffalo_l"}
}
```

`reasons` is the list of plain-language findings behind `flagged`; it is empty
when nothing was found. For a video, the fields roll up the **worst** frame,
not an average: one bad frame in a clean clip is a bad clip.

### Video sampling

`sample_fps` defaults to 1 — plenty for screening, since a frame that appears
for under a second still appears. Frames are sampled uniformly across the
**whole** duration, and when the per-video frame cap binds the rate is reduced
rather than the tail dropped: screening the first four minutes of a ten-minute
video is not screening it.

## Configuring the models

Three roles, each configurable through a `moderation_models` entry:

```jsonc
"moderation_models": [
  {"role": "nsfw", "id": "Falconsai/nsfw_image_detection"},
  {"role": "age",  "id": "iitolstykh/mivolo_imdb"},   // else insightface's own head
  {"role": "face", "id": "buffalo_l"}
]
```

Defaults, with no configuration at all:

* **faces and face_match** — insightface `buffalo_l`, which the image already
  ships for face swapping. Detection plus a 512-d identity embedding.
* **age** — `buffalo_l`'s own genderage head, so age needs no extra download.
  It reports a single number, which this endpoint widens into an interval
  (see above). A configured MiVOLO is the better estimator where you have one.
* **nsfw** — `Falconsai/nsfw_image_detection` (ViT, Apache-2.0). Any
  image-classification model works; labels containing *nsfw*, *porn*, *hentai*,
  *explicit*, *nudity*, *nude*, *sexy* or *suggestive* count toward the score,
  and every label is reported so your policy can differ from the default.

`CODERAI_NSFW_MODEL` overrides the nsfw default without touching the config.

## Notes

* A `face_match` reference with no detectable face is a **400**. Skipping it
  quietly would make every real face read as "matches no consenting performer"
  for the wrong reason.
* Similarity is cosine between embeddings; `0.6` separates identities on
  `buffalo_l`'s recognition head. Raise it for a stricter match.
* Faces are reported per sampled frame, so one person across 60 frames is 60
  entries. `min_age_estimate`, `minor_detected` and `unmatched_faces` are the
  rolled-up answers.
